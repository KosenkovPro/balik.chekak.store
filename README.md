# ЧёКак: Балик / CheKak: Buck

Кроссплатформенное мобильное приложение для учёта личных расходов: импорт банковских выписок
(CSV / XLSX / PDF), автоматическая категоризация, лимиты, прогнозы и аналитика.

**100% offline.** Приложение не запрашивает разрешение `INTERNET`, не обращается к сети,
не отправляет телеметрию. Все данные лежат в локальной базе SQLite (Room KMP) на устройстве.

| | |
|---|---|
| Стек | Kotlin Multiplatform 2.2.10 + Compose Multiplatform 1.9.0 (Material 3) |
| База | Room KMP 2.8.5 + SQLite bundled |
| DI | Koin 4.2 |
| JDK | 21 LTS (`jvmToolchain(21)`) |
| Bundle ID | `store.chekak.balik` |
| Платформы | Android (APK/AAB) — рабочая сборка; iOS — порт в процессе (см. «Сборка → iOS») |

## Что умеет

* **Импорт выписок** — Райффайзенбанк (CSV), Т-Банк (PDF-справка), любой банк в XLSX/CSV.
  Файлы можно выбрать из приложения, открыть из файлового менеджера или передать
  через системное меню «Поделиться» (Android: `ACTION_SEND`/`ACTION_VIEW`, iOS: Share Extension).
* **OCR для сканов PDF** — если в PDF нет текстового слоя (обычный скан выписки),
  приложение само распознаёт картинку и разбирает её тем же кодом, что и обычный PDF.
  Распознавание полностью офлайн: движок и языковые модели лежат внутри приложения,
  сеть не нужна.
  * Android — Tesseract 5.5 (`org.bytedeco:tesseract`) поверх картинки страницы,
    отрендеренной PDFBox-Android;
  * iOS — системный Vision (`VNRecognizeTextRequest`) поверх снимка страницы из PDFKit
    (написано, но ещё не собрано под Kotlin/Native — см. «Сборка → iOS»);
  * JVM (desktop) — распознавания нет, там только тесты.

  Страница рендерится в **300 dpi**: текст справки набран кеглем 7 pt, и при 200 dpi
  глифы выходят слишком мелкими — движок чаще путает кириллицу с латиницей.
  Модели — русская и английская вместе, int-квантованные `tessdata_best`: движок
  Tesseract 3.05 из `tess-two` умеет только старый движок, модели LSTM с ним
  несовместимы. Модели лежат в APK (+10 МБ) и распаковываются при первом запуске.
  На iOS Vision работает сразу с двумя языками, поэтому там отдельных моделей не нужно.

  **Омоглифы.** Кириллические буквы АВЕКМНОРСТУХ неотличимы от латинских, поэтому
  движок, выбирая алфавит по странице целиком, читает «PYATEROCHKA» как
  «РУАТЕВОСНКА», а «ТОО» как «TOO». Переписывать буквы по таблице нельзя:
  «МОСКВА» — настоящее кириллическое слово. Поэтому каждое подозрительное слово
  перечитывается отдельно — латиницей и кириллицей, — и приложение берёт то
  прочтение, которое согласуется с окружением строки: в описании операции
  кириллическая часть («Оплата в») стоит в начале, а латинская (название магазина,
  город, страна) — в конце. Соседние слова с однозначным алфавитом и говорят,
  какой алфавит у омоглифа; страничное прочтение движка при этом не трогается —
  оно лучше фрагментного, фрагмент читается без окружения.

  Скан справки Т-Банка (20 страниц, 200 dpi) разбирается **точно как текстовый слой**:
  473 операции из 473, доходы и расходы совпали до копейки, а описания совпали
  дословно в 457 случаях из 473 (96,6 %), сходство по Левенштейну — 99,8 %.
  Оставшиеся 16 расхождений — не омоглифы, а ошибки распознавания формы символов
  («g» → «9», «п» → «no»). Одна страница — около 7 секунд, поэтому в предпросмотре
  импорта появляется пометка «Текст распознан по картинке (OCR)» — суммы стоит
  сверить глазами.

  То же проверено на собранном APK: release-сборка на эмуляторе импортирует скан
  (473 операции, 0 нераспознанных строк, остаток и суммы совпадают с эталоном),
  а описания, выгруженные прямо из её базы, совпадают с настольным стендом —
  омоглифов среди них нет ни одного.

  Разбор устойчив к огрехам распознавания: знак валюты может пропасть у одной из сумм
  (тогда строка разбирается по колонкам таблицы), кириллическая «О» вместо нуля и
  длинное тире вместо минуса исправляются, слова строки собираются по середине
  рамки — глиф, измеренный движком неточно, не отрывается от своей строки, а
  неверно прочитанное время не выбрасывает операцию целиком.

  Качество движка проверялось на той же справке независимыми OCR — Tesseract 5.5
  с LSTM-моделями на компьютере и RapidOCR (PP-OCR) — через один и тот же код
  разбора. Все нашли 473 операции из 473 и разошлись только в описаниях:
  395 точных описаний у локального Tesseract 5.5 и 333 у RapidOCR PP-OCRv5 против
  457 у движка в приложении. Суммы, остаток, карта и период совпали у всех.
* **Сверка распознанного с оригиналом** — результат OCR можно сверить с исходной
  выпиской прямо в приложении. Выбирается оригинал (PDF с текстовым слоем, CSV или XLSX),
  и приложение сопоставляет операции по дате и сумме, а внутри одинаковых дат и сумм —
  по сходству описаний. Отчёт показывает, сколько операций в оригинале, сколько
  распознано, сколько совпало дословно, среднюю сходность (Левенштейн) и список
  расхождений — с оригиналом, распознанным текстом и процентом сходства рядом.
  Работает и до импорта (из предпросмотра скана), и после (из журнала импортов — по
  конкретному батчу). Оригинал всегда разбирается без OCR: сверять распознанное с
  распознанным бессмысленно, поэтому скан без текстового слоя честно отклоняется
  с понятным сообщением.
* **Слияние выписок за разные периоды** — выписки одного банка пересекаются, поэтому импорт
  не «добавляет всё подряд», а сначала разбирает каждую операцию: что уже есть (пропустить),
  что изменилось (обновить) и чего действительно нет (добавить). Сопоставление идёт от
  надёжного признака к слабому:
  1. **номер документа** — банковский идентификатор операции (в CSV Райффайзена это колонка
     «Номер документа») — не меняется между выгрузками, даже если текст операции поправили;
  2. **отпечаток** — SHA-256 от `банк|дата|сумма|валюта|описание`;
  3. **сумма + время + назначение** — нечёткое сопоставление (допуск 2 минуты, сходство
     текста), если банк поменял формулировку или время.

  Одна сохранённая операция сопоставляется не более чем с одной новой, поэтому две одинаковые
  покупки в один день не склеиваются; при сомнении операция считается новой. Одинаковые
  операции внутри одной выписки (например, два возврата в одну минуту) сохраняются обе —
  им присваивается порядковый номер, а итоги импорта сходятся с итогами в самой справке.
* **Защита от дублей** — SHA-256-отпечаток операции (`банк|дата|сумма|валюта|описание`),
  одинаковые операции при пересекающихся выгрузках импортируются один раз.
* **Переводы самому себе** — отсекаются по номерам своих карт/счетов (настраиваются
  в «Мои счета и карты») и по типовым формулировкам в описании.
* **Категоризация** — трёхступенчатая: детектор переводов → пользовательские правила
  (MCC / «содержит текст» / регулярное выражение) → встроенный справочник MCC.
  В предпросмотре импорта можно поправить категорию и сохранить правило для похожих операций.
* **Аналитика** — дашборд с пончиковым графиком, доли по категориям, итоги по периодам
  (текущий/прошлый месяц, всё время) и **разбивка по валютам** (конвертации нет — курсов
  в offline-приложении быть не может).
* **Прогноз на любую дату** — темп расходов и доходов берётся из выбранного периода
  истории (произвольного: «только прошлый месяц», «3 месяца», «6 месяцев», «всё время»
  или свои даты «с» и «по»), а прогноз считается до выбранной целевой даты (тоже
  произвольной) и показывает, сколько денег будет на этот день. Метод расчёта —
  медиана, среднее или 85-й перцентиль (по умолчанию p85). Выбранный период и дата
  сохраняются: при переходе на другой экран и при перезапуске приложения они не слетают.
* **Вклады** — сумма, ставка, срок и схема начисления процентов (ежемесячно,
  в конце срока, с капитализацией). Рост вклада и налог на проценты считаются по
  правилам НК РФ (ст. 217.1): облагаются проценты свыше необлагаемого минимума
  (по умолчанию 160 000 ₽ за год — 1 млн ₽ × максимальная ключевая ставка ЦБ),
  ставка 13%, а с превышения порога в 2,4 млн ₽ — 15%. Ставки и лимиты редактируются
  в настройках, минимум применяется один раз на год на все вклады сразу.
  Вклады учитываются в прогнозе как отдельный актив.
* **Лимиты по категориям** — месячный бюджет с прогрессом и предупреждением при приближении.
* **Наличные** — отдельный счёт: пополнение, снятие, список операций, попадает в аналитику.
* **Ручные операции** — добавление и полное редактирование (сумма, дата, описание,
  категория, флаг перевода).
* **Резервные копии** — экспорт базы в JSON (читаемый, восстанавливается) и в `.sqlite`
  (точная копия файла БД); импорт JSON-бэкапа.
* **Журнал импортов** — каждый импорт сохраняется как батч, ошибочный импорт откатывается
  одним действием: добавленные операции удаляются, а изменённые возвращаются в прежний вид.
* **Предпросмотр ничего не пишет в базу** — счёт и операции появляются только после
  подтверждения импорта, поэтому отменённый предпросмотр не оставляет следов.
* **Виджет** с итогами месяца (Android AppWidget и iOS WidgetKit).
* **Интерфейс** — русский и английский, Material 3 с динамическими цветами на Android 12+.

## Сборка

### Android

```bash
./gradlew :composeApp:assembleDebug     # отладочный APK
./gradlew :composeApp:assembleRelease   # релизный APK
```

Требуется JDK 21 и Android SDK (compileSdk 36, minSdk 23, targetSdk 35).

### iOS

> **Статус: iOS-таргет ещё не портирован под Kotlin/Native.** Общий код компилируется
> для iOS с ошибками: в `commonMain` остались JVM-only вызовы (`System.currentTimeMillis`,
> `Math`, `String.format`), в `iosMain` недописаны части на PDFKit и Vision. Джоб
> **Actions → Build → iOS unsigned IPA** запускается и показывает прогресс, но пока
> падает и не роняет остальной воркфлоу. Готовый `.ipa` в релиз не входит —
> релизный артефакт сейчас только Android.

Только на macOS с Xcode:

```bash
open iosApp/iosApp.xcodeproj
```

Перед сборкой в Xcode обновляется общий конфиг (идентификаторы, путь к фреймворку
`ComposeApp`, параметры toolchain):

```bash
./gradlew :iosApp:xcodeConfig
```

Для установки на устройство (когда порт будет закончен): `CheKak-Buck-unsigned.ipa`
→ AltStore / SideStore / Sideloadly.

### Тесты

```bash
./gradlew :composeApp:desktopTest       # общие тесты на JVM
```

## Подпись и релиз

Release-сборка Android подписывается ключом из GitHub Secrets:

| Секрет | Назначение |
|---|---|
| `KEYSTORE_BASE64` | base64 файла `.jks` |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | алиас ключа |
| `KEY_PASSWORD` | пароль ключа |

Если секреты не заданы, CI собирает APK с debug-подписью — сборка не падает.

### Сборка со своим ключом подписи

Ключ читается из `.secret/keystore.properties` (файл не в репозитории) либо, если
такого файла нет, — из переменных окружения:

```powershell
$env:KEYSTORE_PATH     = 'D:\keys\my-release.jks'
$env:KEYSTORE_PASSWORD = 'пароль хранилища'
$env:KEY_ALIAS         = 'алиас ключа'
$env:KEY_PASSWORD      = 'пароль ключа'

./gradlew :composeApp:assembleRelease
```

Готовый APK: `composeApp/build/outputs/apk/release/composeApp-release.apk`.
Идентификатор приложения — `store.chekak.balik`.

### Переустановка поверх старой копии

Пока пакет `store.chekak.balik` уже стоит на устройстве, установка APK с **другой**
подписью не пройдёт: система откажется с «Package signature does not match the
installed app». Это не поломка сборки — подпись просто должна совпадать с уже
установленной, либо старый экземпляр нужно сначала удалить.

На Huawei с PrivateSpace и несколькими пользователями удалять надо для всех:
Настройки → Приложения → Приложения → «ЧёКак: Балик» → «Ещё» → Удалить для всех
пользователей. После удаления ставить заново.

## Приватность

* Разрешение `INTERNET` **не запрашивается** ни на Android, ни на iOS.
* Нет аналитики, рекламы, SDK и сетевых вызовов.
* Все данные — в локальной базе приложения; бэкап делается только вручную, в файл,
  который вы выбрали сами.
* Папка `.secret` в репозитории (личные выписки) добавлена в `.gitignore` и не попадает
  в Git.

## Добавление нового банка

1. Реализуйте `BankStatementParser` в `parser/` (интерфейс из `parser/ParsedStatement.kt`).
2. Добавьте парсер в `ParserRegistry`.
3. Больше ничего менять не нужно: UI, база и категоризация подхватят банк автоматически.
